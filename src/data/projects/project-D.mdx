# Introducción

El proyecto **CloudLatam Dashboard** consiste en una API robusta y un panel de control (Dashboard) desarrollados para medir, controlar y visualizar en tiempo real el consumo de recursos operativos y financieros en infraestructuras en la nube.

La solución centraliza endpoints especializados para el control de alertas, análisis de detalles operativos y resúmenes financieros, entregando una interfaz clara y directa para la toma de decisiones técnicas y gerenciales.

## Características Principales

- **Monitoreo de Consumo**: Endpoints dedicados al seguimiento del rendimiento y uso de recursos cloud.
- **Sistema de Alertas Automatizado**: Verificación programada de umbrales críticos de consumo (`check-alertas.js`).
- **Resúmenes Financieros**: Procesamiento y visualización de costos asociados a la operación y uso de la plataforma.
- **Panel Interactivo (Dashboard)**: Interfaz visual alojada en el cliente para la consulta rápida de métricas clave.

## Perspectiva Técnica

La arquitectura está diseñada bajo un modelo modular tipo serverless, optimizado para integrarse de manera fluida y desplegarse en plataformas cloud modernas.

| Capa / Módulo | Responsabilidad técnica |
| :--- | :--- |
| **API Serverless (`/api`)** | Endpoints desacoplados para salud del sistema, alertas, detalles operativos y finanzas. |
| **Frontend (`/public`)** | Interfaz web ligera en HTML/CSS/JS para la renderización del dashboard de consumo. |
| **Testing & Mocks** | Scripts automatizados de prueba (`run_tests.js`) y servidores simulados (`mock_server.js`). |
| **Infraestructura** | Configuración nativa para despliegues rápidos en la nube mediante Vercel (`vercel.json`). |

## Estructura del Repositorio

```text
Dashboard--CLM/
├── api/
│   ├── _shared.js             # Utilidades y lógica compartida para los endpoints
│   ├── check-alertas.js       # Endpoints de verificación de alertas del sistema
│   ├── detalle-operativo.js   # Métricas y detalle del consumo operativo
│   ├── health.js              # Endpoint de verificación de estado (Health Check)
│   ├── resumen-financiero.js  # Cálculo y resumen financiero de consumos
│   └── run-alert-check.js     # Automatización y ejecución de revisión de alertas
│
├── public/
│   └── index.html             # Interfaz visual del dashboard de consumo
│
├── mock_server.js             # Servidor simulado para pruebas locales
├── package.json               # Configuración de dependencias y scripts
├── run_tests.js               # Automatización de pruebas unitarias/integración
├── stitch_integration.js      # Integración con servicios de conectividad
└── vercel.json                # Configuración de despliegue para Vercel
```

## Desafíos y Aprendizajes

- **Diseño de Endpoints Escalables**: Estructurar una API modular en Node.js que permita añadir nuevas métricas de consumo sin acoplar la lógica de negocio.
- **Optimización de Alertas**: Implementar un sistema de verificación capaz de procesar estados y emitir avisos de rendimiento eficientemente.
- **Simulación y Pruebas**: Uso de servidores de prueba (`mock_server.js`) para validar respuestas del dashboard antes de conectar con bases de datos o servicios en producción.

> ⚠️ **Lección aprendida**: Diseñar con una arquitectura modular orientada a servicios serverless facilita enormemente el mantenimiento y las pruebas automatizadas del backend.

## Resultado y Conclusión

El proyecto cumplió con los objetivos de observabilidad para CloudLatam, proporcionando una herramienta clara para auditar el rendimiento y los costos operativos.

- **Eficiencia Operativa**: Reducción de tiempos en la detección de anomalías gracias al sistema de alertas.
- **Claridad Financiera**: Facilidad para revisar resúmenes financieros consolidados en un solo panel.
- **Crecimiento Técnico**: Consolidación en el desarrollo de APIs REST eficientes y despliegues en la nube.
